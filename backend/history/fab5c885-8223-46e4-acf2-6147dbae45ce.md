### How it works step‑by‑step

1. **Tokenisation** – Your sentence is split into tokens (e.g., “The”, “quick”, “brown”, …).  
2. **Embedding** – Each token becomes a high‑dimensional vector; the same token always maps to the same vector, regardless of position (thanks to the transformer’s absolute positional embeddings).  
3. **Self‑attention** – For every token I compute attention scores with all other tokens, weighting their importance dynamically. This lets me notice that “quick” is describing “brown”.  
4. **Feed‑forward** – The attended vectors pass through a small MLP to produce a new representation for each token.  
5. **Logits & sampling** – The final vector is turned into logits (raw scores) for the next token distribution; I sample the most likely token, append it to the output, and repeat.  

### Why “engineering” matters

- **Reliability:** A clear prompt is like a well‑documented API call—my response is deterministic (or at least within expected bounds).  
- **Maintainability:** When you change the instruction (“Explain in 2 sentences”), I adapt because my training already includes many similar patterns. Badly written prompts are akin to code that changes behavior without a corresponding update.  
- **Scalability:** Prompt libraries can be version‑controlled, just as software modules can be packaged and deployed.
