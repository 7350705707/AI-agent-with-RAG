**Assistant:** **Common syntax‑related errors when writing a Python function**

| Error type | Typical mistake (code) | Why it’s a syntax error |
|------------|------------------------|--------------------------|
| **Missing colon** | `def greet(name):` → correct<br>`def greet(name)` | The function definition line must end with `:`. |
| **Incorrect indentation** | `def foo():<br>    print("hi")`<br>`print("done")` | Python uses indentation to delimit the body; mixing tabs/spaces or missing indentation creates a syntax error. |
| **Unmatched parentheses / brackets / braces** | `def f(x): return (x + 1)` → OK<br>`def f(x) { print x }` | C‑style delimiters (`{}`) are not valid Python syntax. |
| **Wrong number of arguments** | `def add(a, b):` correct<br>`def add(a):` or `def add(a, b, c):` (if you meant a different signature) | The colon must be followed by the exact list of parameters you intend to accept. |
| **Missing function name after `def`** | `def greet <br>    print("hi")` | Every top‑level definition needs a name (`def foo():`). |
| **Using reserved keywords as identifiers** | `def if(x):` | Python treats `if`, `else`, etc., as keywords; using them in variable/function names raises a syntax error. |
| **Incorrect string delimiters inside a docstring** | ```python<br>def f():<br>'""" <br>    pass'''``` (mixed triple quotes) | A malformed triple‑quoted string breaks the parser. |
| **Trailing commas in argument lists** | `def g(a, b,):` | The colon introduces an empty list; Python expects a valid expression after it. |
| **Using `=` instead of `:` for parameter default values** (syntax error only if placed incorrectly) | `def h(x = 10)` → OK<br>`def h() x = 10` | The assignment must be part of the argument list, not a stray statement. |

### Quick checklist

1. **`def name(parms):`** – colon at end, correct indentation for body.  
2. No stray `=` or `{}` outside the function block.  
3. Parameter names are valid identifiers (no reserved keywords).  
4. All parentheses `[ ]`, brackets `[[]]`, braces `[{}]` match.  

If any of these rules are violated, Python’s parser will raise a **SyntaxError** at import/execution time.

**Assistant:** **Python “reserved keywords” – what they are and why you can’t use them**

| Keyword | What it does in the language | Why it’s reserved |
|---------|------------------------------|-------------------|
| `assert` | Runs a test that must be true; raises an error if false. | Built‑in function (`assert`) – using the name would hide it. |
| `as` | Used in type‑annotated imports or assignments to keep original name. | Shortcut for “assign as”. |
| `await` | Starts a coroutine’s suspension point (used with `async def`). | Part of the async/await protocol. |
| `break` | Leaves the innermost loop or `for`/`while`. | Control‑flow statement. |
| `class` | Declares a new class definition. | Core OOP construct. |
| `continue` | Skips to next iteration of a loop. | Loop control. |
| `del` | Deletes objects (removes references). | Object‑destruction command. |
| `do` | Not a Python keyword; often mistaken for “do”. | — |
| `elif` | Alternative branch in an `if/elif/else`. | Branching construct. |
| `except` | Catches exceptions in a `try…except` block. | Exception‑handling mechanism. |
| `for` | Iterates over sequences, containers, etc. | Looping construct. |
| `from` | Starts an import statement (`from module import …`). | Import syntax. |
| `global` | Refers to the global namespace in a function. | Variable scope control. |
| `if` | Conditional expression that starts a block. | Control‑flow branching. |
| `import` | Brings a module into the current namespace. | Module loading. |
| `in` | Membership test (`x in iterable`). | Expression evaluation. |
| `is` | Identity comparison (object identity). | Equality test for objects. |
| `lambda` | Creates an anonymous function object. | Functional‑programming construct. |
| `nonlocal` | Accesses a variable from the nearest enclosing scope that is not global. | Variable‑scope handling. |
| `not` | Logical negation. | Boolean operator. |
| `or` | Logical OR. | Boolean operator. |
| `pass` | No‑op statement; placeholder for empty block. | Syntax filler. |
| `raise` | Triggers an exception (often used to re‑raise). | Exception propagation. |
| `return` | Ends a function with a value (or `None`). | Function exit. |
| `try` | Starts a `try…except/finally` block for error handling. | Control flow around errors. |
| `while` | Repeats code while a condition is true. | Loop control. |

### Key points to remember

1. **You cannot assign to them** – e.g., `x = if` or `y = and` will raise a `SyntaxError`.
2. **They are case‑sensitive** – only the exact capitalisation shown above matters.
3. **Some act as functions, some as statements** (e.g., `assert`, `break`, `continue`). Trying to use them where they aren’t allowed produces a syntax error at parse time.
4. **Python’s tokenizer looks for these tokens before it builds an abstract‑syntax tree**. If the token is found in a context that doesn’t expect one, the parser aborts with a syntax error.

### Quick example

```python
if if:          # SyntaxError: invalid syntax
    print("hello")
```

The second `if` is a reserved keyword used for conditionals; using it as a variable name inside an `if` statement confuses the parser and triggers a syntax error.
