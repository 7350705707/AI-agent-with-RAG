**User:** explain me what is github

**Assistant:** **GitHub** is a cloud‑based service that lets developers store and share code—usually in the form of **software projects**—and collaborate on them together.

| What it does | How it works |
|--------------|--------------|
| **Version control** (Git) | Every change to a project is recorded as a *commit*. GitHub automatically keeps a history so you can roll back or compare versions. |
| **Repository hosting** | A *repository* (repo) is a folder that contains all the files of a project plus its commit log. You create one on GitHub and others can clone it to their own machines. |
| **Collaboration tools** | • **Pull requests** – propose changes; reviewers comment or merge them.<br>• **Issues & Projects** – track tasks, bugs, and work‑flows.<br>• **Code reviews** – other developers examine the code before it’s merged. |
| **Integration with CI/CD** | GitHub Actions can automatically run tests, build binaries, deploy apps, etc., whenever a push or pull request is made. |
| **Public vs private repos** | Public repos are free to view; private repos require a paid plan (e.g., GitHub Team/Enterprise). |

### Example (Indian context)
- A startup in Bangalore creates a web app and pushes its code to a private GitHub repo.
- The team uses pull requests for each feature, allowing members across India (or globally) to review the code without exposing source files.
- When a new version is ready, GitHub Actions automatically runs unit tests and deploys the updated site to a staging server.

### Why developers use it
1. **Safety** – automatic backups via commits.  
2. **Speed** – instant sharing; no need for email attachments or FTP.  
3. **Quality control** – peer reviews catch bugs early.  
4. **Continuous delivery** – automated pipelines reduce manual steps.

In short, GitHub is the “Git” (version‑control system) plus a web portal that makes it easy to work together on code.
