### 1. What is GitHub?
- **Definition:** GitHub is a web service that hosts *repositories* (code projects) and the version‑control system *Git*.  
- **Purpose:** It lets developers store, track changes to their code, collaborate in real time, and deploy software safely.

---

### 2. Core Concepts

| Term | Meaning |
|------|---------|
| **Repository (repo)** | A folder that contains all files of a project plus the commit log (history). One repo = one logical project. |
| **Commit** | A snapshot of the repository at a point in time, recorded with a timestamp and author. |
| **Branch** | An independent line of development; every feature or bug‑fix lives on its own branch. |
| **Pull Request (PR)** | A request to merge changes from one branch into another (usually `main`/`master`). GitHub reviews the PR before merging. |
| **Fork** | A copy of a repo owned by someone else, used to experiment or contribute without affecting the original. |
| **Issue** | A ticket for a problem, suggestion, bug report, etc., attached to a repo. |
| **Project** | A collection of repos that belong together (e.g., all code for an app). |

---

### 3. How It Works – Step‑by‑Step Workflow

1. **Create / Clone a Repo**  
   - *Owner* creates the repo on GitHub → `git clone https://github.com/owner/repo.git`.  
   - Others can also create their own repos or fork an existing one.

2. **Make Changes Locally (Git)**  
   ```bash
   git add .                # stage changes
   git commit -m "msg"      # record a new commit
   ```

3. **Push to GitHub**  
   ```bash
   git push origin main    # sends commits to the remote repo
   ```
   → Each commit appears on GitHub with a unique SHA.

4. **Branch & Pull Request**  
   - `git checkout -b feature/login` creates a branch.  
   - Push this branch: `git push -u origin feature/login`.  
   - On GitHub, click “Compare & pull request” → opens a PR.

5. **Review & Merge**  
   - Reviewers comment, suggest fixes, approve.  
   - Once approved, you *merge* the PR (GitHub creates a merge commit or squash‑merge).

6. **Deploy / CI/CD Integration**  
   - GitHub Actions automatically runs tests on every push to `main`.  
   - Deploy pipelines can push Docker images to ECR/AKS/etc.

7. **Forking for Contributions**  
   - Contributors fork the repo → clone their copy locally → make changes → open a PR against *their* fork.

### 4. Why Developers Use GitHub (Indian Context)

| Benefit | Indian‑Specific Example |
|---------|--------------------------|
| **Free tier** – Sufficient for most personal projects, startups, and school assignments. |

| **Open‑source community** – Projects like *Python‑Geeks*, *DevOps‑India* thrive on GitHub; contributors can earn badges recognized by companies. |
